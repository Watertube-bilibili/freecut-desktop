# 0.3.2 导出、音频识别与快捷方式修复验证

本次更新包括导出架构调整、带专辑封面的音频识别与旧工程修复，以及覆盖安装后的旧快捷方式和图标刷新。当前为源码验证记录，尚不表示 0.3.2 已发布；正式构建和公开安装包的验收需使用对应 Release 记录。

## 导出架构

导出由程序自动选择处理路径，未增加要求用户判断的新模式：

- 符合条件的普通视频、静态图片、顺序裁剪拼接和常速变速直接交给 FFmpeg。原生规划保留工程背景、画幅内等比缩放、片段间隙和隐藏视频轨道；音频使用工程原有混合规则。
- 文字、形状、视觉关键帧、淡入淡出、蒙版、调色、画面叠加等未纳入原生等价范围的内容继续交给共享 Canvas 合成器，不会跳过效果。非输出帧边界的切点、超出源范围等暂不支持的组合也使用兼容路径。
- 兼容路径把 RGBA 画面直接送入 FFmpeg 标准输入，边渲染边编码，不再为每帧生成和读取临时 PNG。发送端等待当前帧写入完成再送下一帧，以背压控制待发送数据，避免排队缓存整部影片。
- 导出进度约每 100 ms 更新；H.264 编码使用 x264 的 `veryfast` 预设和 4 个编码线程。编码仍使用 CPU；未据此声称启用了 GPU 编码。

`node --test electron/native-export.test.cjs` 的 5 项测试已分别通过开发引擎和此前 0.3.1 公开包内的 FFmpeg 9.0.1。真实小样本检查 1.8 秒、18 帧输出，逐一核对剪辑切点、前中后空隙、隐藏轨道、contain 背景及半透明 PNG；另检查 2× 和 0.5× 变速的颜色切换帧，以及非整帧总时长的最后一帧。该测试验证规划器正确性，不是新版本完整安装包验收，也不是性能基准。

原生路径与 Canvas 在解码、缩放和色彩舍入上可能存在差异；特殊 SAR、ICC/HDR 和 VFR 素材尚未单独完成等价验收。复杂效果仍需逐帧定位、解码和合成。更少的中间文件不等于所有工程和机器都同样快；本次使用相同工程、输出参数和设备的新旧导出耗时对照尚待记录，不引用小样本编码时间作为通用提速倍数。

## 音频封面与旧工程

媒体探测忽略 `attached pic` 专辑封面流，仍继续查找真实视频流。只有音频和封面的文件按音频导入；同时存在真实视频的文件仍保留为视频。打开、恢复或重新链接旧工程素材时同步修正此前错误的素材和片段类型，保留原片段位置、时长、轨道与音量关键帧。

相关验证位于 `electron/media.test.cjs` 和 `scripts/regression-media-kind.cjs`，覆盖带封面音频、真实视频优先、旧工程类型修正及实际应用行为。新增导出兼容管道与完整媒体回归的最终执行结果由本次构建记录汇总；本段不把旧版本的检查结果当成新管道已通过的证明。

## Windows 快捷方式

- `node --test installer/backend.test.cjs installer/shortcuts.test.cjs`：23 项测试通过，其中实际 Electron Shell Link 测试包含 19 种新装、旧版迁移、8.3 别名、自定义入口及独立图标情形。
- `node installer/smoke.cjs`：6 组真实安装界面、取消/重试、升级及 PowerShell 卸载验证通过。桌面/开始菜单使用隔离目录，图标文件、图标散列与快捷方式读取结果一致。
- Unicode 卸载回归继续在 ACP1252 的独立进程中验证中文目录和说明；升级后的独立 ICO 随安装清单归属管理。
- `--no-shortcuts` 供无人值守安装使用，真实 Setup 打包回归通过该参数避免更新开发者自己的桌面入口。默认安装和应用自动更新会更新符合条件的旧入口。

新图标以内容 SHA-256 命名，避免沿用旧 EXE 图标路径。安装后发送 Shell 变更及缓存失效通知，不删除 Windows 全局缓存文件、不重启 Explorer。实现参考微软的 [SHChangeNotify 文档](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify)和[快捷方式图标刷新说明](https://devblogs.microsoft.com/oldnewthing/20150903-00/?p=91671)。

本地测试与最终发布包验收分别记录；正式构建、安装和完整导出回归结果见本次 Release 及 README。
