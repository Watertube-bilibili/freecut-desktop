# 0.3.2 导出、音频识别与快捷方式修复验证

本次更新包括导出架构调整、带专辑封面的音频识别与旧工程修复，以及覆盖安装后的旧快捷方式和图标刷新。[0.3.2 预览版](https://github.com/Watertube-bilibili/freecut-desktop/releases/tag/v0.3.2-preview.1)已发布，源码提交为 `aba5cacce40047ded37d712f04ef30ca600b78f5`；[三平台构建 34140392722](https://github.com/Watertube-bilibili/freecut-desktop/actions/runs/34140392722)和[发布校验 34141085758](https://github.com/Watertube-bilibili/freecut-desktop/actions/runs/34141085758)均成功。下文区分源码、公开包及本机覆盖安装的验证范围。

## 导出架构

导出由程序自动选择处理路径，未增加要求用户判断的新模式：

- 符合条件的普通视频、静态图片、顺序裁剪拼接和常速变速直接交给 FFmpeg。原生规划保留工程背景、画幅内等比缩放、片段间隙和隐藏视频轨道；音频使用工程原有混合规则。
- 文字、形状、视觉关键帧、淡入淡出、蒙版、调色、画面叠加等未纳入原生等价范围的内容继续交给共享 Canvas 合成器，不会跳过效果。非输出帧边界的切点、超出源范围等暂不支持的组合也使用兼容路径。
- 兼容路径把 RGBA 画面直接送入 FFmpeg 标准输入，边渲染边编码，不再为每帧生成和读取临时 PNG。发送端等待当前帧写入完成再送下一帧，以背压控制待发送数据，避免排队缓存整部影片。
- 导出进度约每 100 ms 更新；H.264 编码使用 x264 的 `veryfast` 预设和 4 个编码线程。编码仍使用 CPU；未据此声称启用了 GPU 编码。

`node --test electron/native-export.test.cjs` 的 5 项测试已分别通过开发引擎和此前 0.3.1 公开包内的 FFmpeg 9.0.1。真实小样本检查 1.8 秒、18 帧输出，逐一核对剪辑切点、前中后空隙、隐藏轨道、contain 背景及半透明 PNG；另检查 2× 和 0.5× 变速的颜色切换帧，以及非整帧总时长的最后一帧。该测试验证规划器正确性，不是新版本完整安装包验收，也不是性能基准。

原生路径与 Canvas 在解码、缩放和色彩舍入上可能存在差异；特殊 SAR、ICC/HDR 和 VFR 素材尚未单独完成等价验收。复杂效果仍需逐帧定位、解码和合成。更少的中间文件不等于所有工程和机器都同样快。

同机实际应用 UI 对照：i5-13500H、16 GB 内存，相同 SHA-256 的 FFmpeg 9.0.1、相同 5 秒原创视频、720p/24 fps、标准质量 CRF 23。仅计点击导出至“视频已保存”，不含导入和验收。0.3.1 使用 medium，0.3.2 使用 veryfast；每项各测一次，包含架构和编码预设共同变化，不是所有设备的性能承诺。

| 常规单视频 | 18.025 秒 | 3.070 秒 |

四个输出均完整解码通过：120 帧、5 秒、1280×720、24 fps、AAC 有声、画面非黑、0 个渲染错误。常规剪辑在本次测试中提速；叠加兼容路径未提速，不能宣传全场景加速。

新导出管线另有 3 项真实 FFmpeg 测试：原生输出无需 IPC 帧且音频索引正确；RGBA 写入期间编码器已启动且无逐帧临时文件；取消、无效帧及实际编码失败保留已有输出，并回收编码器与临时目录。使用公开版 FFmpeg 9.0.1 同样通过。7 组实际预览检查及 7 组效果/布局检查通过，包含快速拖动无黑帧、严格导出与并发预览独立，以及蒙版和关键帧像素。

## 音频封面与旧工程

媒体探测忽略 `attached pic` 专辑封面流，仍继续查找真实视频流。只有音频和封面的文件按音频导入；同时存在真实视频的文件仍保留为视频。重新打开旧工程时，会重新读取可用素材并同步修正此前错误的素材和片段类型，保留原片段位置、时长、轨道与音量关键帧。

相关验证位于 `electron/media.test.cjs` 和 `scripts/regression-media-kind.cjs`。真实带封面 FLAC/M4A、音频 MIME 与非静音解码通过；原生导入、保存、重开旧工程及无画面变换控件的实际 UI 检查通过，0 个渲染错误。测试引擎无 libmp3lame 时仅显式跳过 MP3 测试素材生成，不跳过 FLAC/M4A 检查，也不为测试扩大发布引擎依赖。

## Windows 快捷方式

- `node --test installer/backend.test.cjs installer/shortcuts.test.cjs`：23 项测试通过，其中实际 Electron Shell Link 测试包含 19 种新装、旧版迁移、8.3 别名、自定义入口及独立图标情形。
- `node installer/smoke.cjs`：6 组真实安装界面、取消/重试、升级及 PowerShell 卸载验证通过。桌面/开始菜单使用隔离目录，图标文件、图标散列与快捷方式读取结果一致。
- Unicode 卸载回归继续在 ACP1252 的独立进程中验证中文目录和说明；升级后的独立 ICO 随安装清单归属管理。
- `--no-shortcuts` 供无人值守安装使用，真实 Setup 打包回归通过该参数避免更新开发者自己的桌面入口。默认安装和应用自动更新会更新符合条件的旧入口。

新图标以内容 SHA-256 命名，避免沿用旧 EXE 图标路径。安装后发送 Shell 变更及缓存失效通知，不删除 Windows 全局缓存文件、不重启 Explorer。实现参考微软的 [SHChangeNotify 文档](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify)和[快捷方式图标刷新说明](https://devblogs.microsoft.com/oldnewthing/20150903-00/?p=91671)。

## 公开包与覆盖安装

- 从公开 Release 重新下载 Windows Setup、Portable、中英文入门说明和 SHA-256 清单，逐项核对 GitHub 资产摘要及清单。Setup 为 119,673,463 字节，SHA-256 为 `03dcc306b89e5c889db6ff794727a52c5714d6a3a474155594c40bd0da3b5a3d`；Portable 为 106,123,420 字节，SHA-256 为 `16cf8f8e02ec4e80c34e44ea4de44e304f0100848da9db273d24916766bd070d`。
- 使用 Computer Use 操作公开原版 Setup 的自定义安装界面，一键覆盖安装到 C 盘原有用户程序目录。升级前通过应用保存当前未保存工程，再正常退出旧版；覆盖安装完成，安装清单显示 0.3.2，EXE 产品版本为 0.3.2.0，安装后的 `app.asar` 与公开 Portable 解包内容一致。
- 本机此前为处理旧图标而创建的临时 ICO 遇到 Codex MSIX 目录虚拟化：安装器将它识别为自定义图标并保留，资源管理器显示空白图标。已备份两条默认属性的 FreeCut 快捷方式，仅将其图标位置迁移到安装目录内的独立 ICO，其余属性保持；目标图标散列与安装清单一致，两条入口的实际 Electron 迁移检查均返回 `replace`。随后通过 Computer Use 查看资源管理器的桌面文件夹，确认显示新的绿色 3D 图标，并通过该桌面入口启动应用，首页显示 0.3.2。
- 在真实 C 盘安装版重新打开升级前保存的双片段宣传片工程，FLAC 已从视频恢复为音频；选中后显示音量、左右声道等控制，预览无缩放和旋转框。原片段时长分别保持 55 秒和约 54.98 秒，原始媒体及升级前保存的工程文件保留。随后正常退出应用。

本地性能对照使用前述指定工程；发布 CI 另覆盖真实导出与媒体回归。安装成功与测试通过不代表所有硬件、长工程和素材均已验证。
