# 0.4.0 连续预览与自建协作验证

更新日期：2026-09-14。本次代码包含连续播放预览修复、无需项目方服务器的协作房间、工程三方合并和授权素材传输。生产构建、本轮全量单元测试、连续预览及两个真实 Electron 窗口的协作界面检查已通过。**目前不代表 0.4.0 公开安装包或三平台 CI 已通过**；发布验证状态在下方单独列出。

## 连续预览

此前播放路径频繁给媒体设置 `currentTime`，导致解码器不断重新定位。新路径在连续播放时复用持续运行的媒体解码器，按预览绘制节奏读取画面；拖动、跳转、暂停和导出的严格取帧分别处理，过时预览请求会被合并。它没有增加代理文件、自动转码或硬件编码功能。

已读取 Windows 本地回归报告 `freecut-playback-regression-eMwpQ4/playback-report.json`。报告 `passed: true`，`rendererErrors: []`，包含合成器与真实编辑器两部分。

| 检查 | 实测结果 |
| --- | --- |
| 合成器连续播放 | 212 次采样观察到 105 个不同源帧，仅 1 次 seek；P95 时间落后约 69.7 ms，最差约 73.4 ms。 |
| 播放时跳转 | 35 次采样观察到 19 个不同源帧，仅 1 次 seek；跳转窗口 P95 时间落后约 244.0 ms，最差约 244.6 ms。仍存在跳转后的解码追赶，不能宣称零延迟。 |
| 2× 速度播放 | 73 次采样观察到 54 个不同源帧，仅 1 次 seek；P95 时间落后约 64.7 ms，最差约 65.5 ms。 |
| 拖动定位 | 15 个完成的拖动请求得到 15 个不同画面。 |
| 严格取帧 | 1/30 秒、7.1 秒、10.5 秒、0.2 秒分别取得源帧 1、213、315、6；与连续预览并存的严格取帧仍准确。 |
| 真实专业布局 | 187 次采样观察到 90 个不同画面；预览与时间线的 P95 差约 33.3 ms，最差约 100.0 ms。 |
| 真实手机风格布局 | 170 次采样观察到 84 个不同画面；预览与时间线的 P95、最差差值均约 33.3 ms。 |
| 离开编辑器 | 报告确认媒体解码器暂停；结束统计中 `playingVideos: 0`。 |

整个合成器测试记录了 603 个请求、340 个提交、263 个合并掉的过时请求和 22 次 seek。请求合并数字包含连续播放、跳转、拖动和严格取帧等不同测试阶段，不能把它换算成某段影片的丢帧率。上表不同画面数量为对应测试窗口的采样结果，也不是所有机器稳定达到某个 FPS 的承诺。

本报告只证明测试素材与本机运行范围。低配笔记本、长工程、多路高分辨率叠加、VFR/HDR/特殊编码和无法由 Chromium 解码的媒体，仍需要分别验收。复杂效果仍受 CPU、浏览器解码与绘制成本限制。

## 协作后端

执行 `node --test electron/collaboration.test.cjs`：**9 项通过，0 失败，0 跳过**。使用真实 HTTP 监听与客户端、临时文件和隔离资料目录，不依赖公共服务器。

1. 房主与加入方实际双向同步工程修订；不同片段属性修改自动合并，同一字段冲突不改变调用方草稿；事件来源 ID 可区别自己提交的确认与远端修改。
2. 二进制素材实际双向流式传输、SHA-256 校验和本机落盘；房主路径与 `freecut-media` 访问令牌不出现在原始网络工程消息中；退出后本地文件保留。
3. 错误房间密钥、浏览器 Origin、目录穿越、未声明上传、超限 JSON、带远端路径的工程和未经本机导入授权的源文件被拒绝。
4. 端口占用失败后返回断开状态；新房间不能直接发布或读取上一房间的缓存素材，即使请求方已知其内容散列。
5. 固定 IPv4 与端口校验、每文件大小限制、非法扩展名、编辑与删除冲突检查。
6. 同时发起 12 次加入请求时，除房主外只接受 7 人，其余返回人数限制；散列不符的上传不会发布或变成可读取素材，临时文件被清理。
7. 真实上传仍在进行时离开，连接中止且部分文件清理；同一个服务可重新创建房间，使用新密钥。
8. 单独合法但组合后无效的修改被拒绝：房主将片段从 5 秒缩短至 2 秒，加入方在旧版本的第 4 秒添加关键帧，合并不会生成越界关键帧，也不会覆盖草稿或推进房主修订。
9. 使用真实 `createMediaLibrary`、真实 FFmpeg 和生成的 PCM WAV 完成导入、下载及本地授权；房主离开后，加入方通过真实导出器生成 MP4，重新探测为视频，解码音频有非零且达到阈值的信号。

前八项主要验证网络、工程与文件协议，其中媒体授权适配器使用隔离测试实现；第九项单独验证实际媒体库和 FFmpeg 的闭环，不能把所有二进制传输测试都说成完整视频 UI 测试。

实现边界：

- 用户主动创建房间才监听 IPv4，默认端口 45823；通过 IP、端口、48 位十六进制随机密钥或邀请码加入。邀请码仅封装这些参数，不自动提供穿透或中继。
- 当前使用 HTTP，适用于可信局域网或已建立的 VPN。浏览器 Origin 请求被拒绝，未实现 TLS、账号、只读角色或公网服务。不同地点的用户需要先具有能连通该地址的网络。
- 网络工程经过字段白名单和编辑器参数校验，只传当前工程授权的素材内容，不传任意本机路径。先流式校验再导入，单文件最多 8 GiB、共享素材总量最多 32 GiB、256 个素材、8 位编辑者、4 路并行传输；会话缓存还有配额和磁盘余量检查。
- 较长的素材上传、下载、准备与发布会维持参与者活动状态，避免正常传输被 90 秒离线清理误移除；空闲事件流返回轻量元数据。
- 最近 24 个修订用于三方合并；历史过旧、同字段冲突或合并后工程无效时，客户端需要处理冲突。没有永久操作日志、自动重连、同步播放头、远端导出或远端 AI 任务。
- 下载的素材保留在应用数据目录，以支持断开后保存、预览和导出；工程仍引用这些本机文件。退出会关闭监听与传输，不自动删除仍可能被已保存工程引用的完整素材。
